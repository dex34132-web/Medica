Download & storage rules

Managed by the Local Model Manager (§04).

Downloads only need connectivity onceAfter install the model works fully offline — the internet is used for delivery, never for inference.
Safe updatesNew versions staged and signature-verified when online, atomically swapped, rollback on failure.
User controls storageSwitch or delete models anytime; only one model is loaded at a time, others rest on disk.
No model on device?Medica still answers from the vault using rules-mode fallback until a model is downloaded.

Local Model Manager

Owns every model artifact on the device — discovery through safe update.

Model discoveryScans installed artifacts, registry manifests, and staged downloads.
Model compatibilityValidated against probe results: RAM, ops, quantization, tokenizer, runtime.
Loading & unloadingLazy load on demand, pin the hot model, release memory under pressure.
Quantized variants4-bit / 8-bit / fp16 per model; picks the largest that fits the tier.
Model versioningSemantic versions, rollbacks, N-1 kept during upgrades.
Storage managementQuotas, LRU eviction of unused variants, vault vs. model budget split.
Memory managementReserved inference arena, KV-cache caps, low-memory callbacks.
Runtime selectionBinds the best available provider from the abstraction layer.
Safe model updatesStaged when connectivity exists; verified before activation, atomic swap, rollback.

Privacy Boundaries

two boundaries · one router
on-device boundary · offline path
Case data stays on-device by defaultRecords, vitals, and notes live in app-private encrypted storage.
Media stays local by defaultPhotos, video, audio from the field are not uploaded for analysis.
No cloud request required for offline analysisInference, retrieval, and reasoning complete with networking disabled.
No cloud API key stored on the deviceNothing to leak — provider credentials live server-side only.
Local models never send the case to a serverPrompts, embeddings, and outputs stay in process memory.
cloud boundary · online path
Used only when the internet is thereReachability is probed per request; unreachable → immediate local fallback.
Only the active request packet leaves the deviceCase stays stored locally; cloud holds no copy, no key on device.
Cloud also delivers updatesSigned model and vault updates staged when connectivity exists.

Local Resilience & Integrity

degrades gracefully, never silently
Local Caching Embeddings, retrieval results, and recent inferences cached in app storage for instant repeat access. query → cache → model
Encrypted Storage Case data, media, models, and index encrypted at rest (Keystore-backed keys, app-private dirs). AES-256 · keystore-backed
Model Integrity Verification Signature and hash verified before load and before index rebuild; corrupt artifacts are rejected. signed manifest · sha-256
Resource Versioning Every vault resource carries a revision; retrieval results are stamped with the version they came from. vault vN · reproducible citations
Graceful Fallback Cloud unreachable, model missing, or device too small — Medica steps down deterministically instead of failing. always returns a usable answer
